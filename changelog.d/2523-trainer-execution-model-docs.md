### Fixed

- **training**: the `Trainer` ABC describes both execution models instead of only the local one. Its module docstring, class docstring, `train()` and `status()` all asserted that concrete trainers import a training library and call it in-process, so `train()` blocks and returns a terminal result and "there is no detached job to poll" - true of six of the seven shipped providers, but not of `sagemaker`, which imports no training library and submits a managed job whose `train()` can return `status="running"` with a `job_id` and no `checkpoint_dir`. A caller reading the old contract treats "not `error`" as finished and reports a completed run that has not finished. The prose is now graded against the providers: the statuses each shipped provider's `train` can return are read out of the code and the ABC must name them, so a provider that starts returning a further status is graded on arrival. `docs/training/overview.md` gains the missing `sagemaker` provider row and states the difference. No behaviour change.
