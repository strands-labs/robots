### Fixed: the sim teleop fence in `docs/hardware/teleoperation.md` no longer passes `robot_name=` to `attach_teleop`

The "Teleoperate a simulation (MuJoCo)" example called `sim.attach_teleop("so101_leader", port=..., map_fn=..., robot_name="arm0")`. `attach_teleop` forwards every keyword it does not read to `Teleoperator()`, whose config filter refused `robot_name` with `ValueError: Unknown kwarg(s) for teleop_type='so101_leader': ['robot_name']` before any device was touched, so the fence failed for every reader, hardware or not. The fence now passes `robot_name` only to `teleoperate()`, which is where the target robot is read, and a docs grader resolves every documented `attach_teleop("<type>", ...)` keyword against the mixin's own arguments and the lerobot config dataclass the factory consults.
