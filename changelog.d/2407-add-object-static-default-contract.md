### Fixed

- **simulation**: `add_object`'s declared `is_static` default is now the one a backend delivers. The base contract declared `is_static: bool = False`, but the default backend cannot deliver that value for `shape="plane"` - a plane is infinite and cannot carry a dynamic mass, so MuJoCo distinguishes "unspecified" from an explicit `False` and takes `bool | None = None`. Omitting the argument returned a **static** plane under `status="success"`, while restating the base-declared `False` was refused outright. `is_static` is now declared `bool | None = None` on the base and on all three backends, with the sentinel's meaning stated: a backend MAY derive the answer from `shape`, and one with no shape-derived rule resolves `None` to `False`. No backend's behaviour changes - a plane handed an explicit `is_static=False` is still refused rather than silently overridden - and the agent schema now describes the parameter it previously published with no description at all.
