### Fixed

- **tests/mesh**: a camera-offload test no longer leaves `sys.modules` without its `boto3` entry. `test_boto3_missing_returns_none` ended with a bare `sys.modules.pop("boto3", None)`, and a removal does not undo an import - it orphans every reference already bound to that module, so the module-level `import boto3` in the e-stop fan-out tests kept an object no later `import boto3` returns. Their `monkeypatch.setattr(boto3, "client", ...)` double was then installed where nothing would look and the real SDK was used instead: run in that order, those tests build a real client and attempt a signed AWS request, failing with `NoRegionError` or `NoCredentialsError` depending on the ambient AWS configuration. The pop was redundant - the `builtins.__import__` block above it already makes the import raise `ImportError`, which is what the test asserts, and monkeypatch undoes it. `tests/test_sys_modules_removal_leaves_no_orphan.py` now derives the rule from the tree: a module a test binds at module level and patches an attribute on may not be removed without restoration, while purging a module nothing patches, to force a re-import, stays legal.
