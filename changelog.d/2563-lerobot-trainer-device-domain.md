### Fixed

- **training/lerobot**: `LerobotTrainer.validate` now reports a `device` no torch build can parse, instead of returning an empty list - which its contract defines as "the spec is launchable". `device` is the trainer's one constructor knob and reaches lerobot twice, interpolated into `--policy.device=` (and `--reward_model.device=`) by `build_command` and assigned onto `policy_cfg.device` by `build_config`, so `device="gpu"` (or `"CUDA"`, `"nvidia"`, `"cuda:abc"`) previously passed preflight and aborted the run before its first step. The admitted set is torch's own - the value is handed to `torch.device` rather than compared against a copied list of device types - and only the spelling is graded, never availability, so a spec naming a device the machine writing it does not have still validates. `device=None` and `""` continue to resolve through the auto-detected default, and with torch unimportable the value passes through unguarded.
