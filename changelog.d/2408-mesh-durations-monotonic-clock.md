### Fixed

- **mesh**: every duration the mesh measures for itself is measured on `time.monotonic()`. Peer liveness was the consequential one: `PeerInfo.age` and `prune_peers` compared two `time.time()` readings, so a wall-clock step - an NTP correction, a `date -s`, a resume from suspend - moved every peer's apparent age by the size of the step. Forward, `prune_peers` runs on each 2 Hz heartbeat tick, so a step past the 10s `PEER_TIMEOUT` deleted the whole fleet in one tick while every peer was still heartbeating; backward, a peer that had genuinely stopped heartbeating went on being reported live for the size of the step, and `age` was reported negative. The same step also inverted the `STRANDS_MESH_MAX_PEERS` flood guard, which evicts the oldest heartbeat and so evicted the freshest peer instead. The LiDAR state publish interval and the `hz_actual` an input publisher/receiver reports were on the same clock and move with it. Absolute stamps are unchanged: a published envelope's `t` field, and the age an input receiver computes against a *remote* peer's `t`, name a point in time another machine correlates and stay on the wall clock.
