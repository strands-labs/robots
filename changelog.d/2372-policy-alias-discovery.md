### Fixed

- **policies**: `strands_robots.policies.list_aliases()` and `strands_robots.registry.list_policy_aliases()` now report the provider alias to canonical mapping, so every spelling `create_policy` accepts is discoverable. `create_policy` resolves a provider by its canonical name or by any `aliases`/`shorthands` its `registry/policies.json` entry declares, but `list_providers()` reported only the 14 canonical names while `create_policy` accepted 28 spellings, leaving `lerobot`, `sonic`, `moveit`, `cumotion`, `text2motion`, `random`, `test` and seven more discoverable only by reading the registry JSON. `list_providers()` already listed aliases registered at runtime through `register_policy`, so visibility depended on which registry a provider lived in, and both `docs/policies/overview.md` and `docs/api-reference.md` described a coverage the function did not have. `set(list_providers()) | set(list_aliases())` is now every accepted spelling; `list_providers()` itself is unchanged, since the provider table it backs is pinned to exactly the canonical set. The new surfaces mirror the robot registry's existing `list_aliases()`, including omitting the inert entries where a provider repeats its own name among its aliases.
