### Fixed

- **simulation**: `BenchmarkProtocol.on_episode_start` now reports a refused `default_robot` instead of running the episode against a robotless scene. The hook auto-loads `default_robot` when the sim is empty and discarded the envelope `add_robot` returns, so a spec naming a hardware-only registry entry, an asset that is not on disk, or a model the backend cannot load reported `status="success"` with `success_rate: 0.0` and `success_measured: True` over a scene with no robot in it. The refusal now raises with the backend's reason attached - the same shape `DeclarativeBenchmark.on_episode_start` already uses for its own `load_scene` envelope - and `PolicyRunner.evaluate` surfaces it as a structured error naming the spec, so a setup failure is distinguishable from a policy that scored zero.
