### Added: ROS 2 robots — `Robot(..., driver="ros")`, `ros.connect()` and the `use_ros` tool

A ROS 2 robot is now a hardware `Robot` driven from a JSON profile. The built-in profiles are `ros2_control` (`/joint_states` in, a forward position controller out) and `unitree_g1` (`/lowstate` and `/lowcmd` at 500 Hz with Unitree's CRC; writes are refused until `released=True`). One command stream owns each robot's command topic and runs on a timer or answers every sensor frame. A late policy gets its last target repeated, a missing one gets the measured pose held, and the stream never damps. `shadow=True` builds every command, publishes none, and reports the gap to a reference topic. kp/kd from `Robot.set_gains` or a policy go out with each command. `use_ros` lets an agent list, echo, call, set parameters, look up TF and record. Every write needs an exact `STRANDS_ROS_ALLOW` entry or an operator's yes (only publishes to `/rosout`, `/diagnostics` and the marker topics are free); that covers parameter writes (`set_param` is gated as `<node>/set_parameters`) and the controller manager's services, and a topic a `Robot` streams is always refused. Each write is checked on the name it runs on (`publish` its topic, `call` its service, `goal` its action, `set_param` its node), and a second target key is refused. `stop` needs no yes, so it sends only the stop sequence of an installed profile, by name, never a file path. A `Float64MultiArray` command carries no joint names, so its slots follow the controller's `joints` parameter (read at connect, or `command.joints` in the profile); connect refuses without one, or when it is not exactly the model's joints. Robots outside this repo plug in through `STRANDS_ROBOTS_ROS_PROFILES` or the `strands_robots.ros_profiles` entry point, with codecs from `"codec": "pkg.mod:Class"` or `strands_robots.ros_codecs`. rclpy comes from the ROS install, never from pip, and `import strands_robots` never imports it. A URDF is now introspected with the XML walk, because MuJoCo's import gave it no action keys; the walk reads only the `<joint>` elements directly under `<robot>` (not those inside `<ros2_control>`, `<transmission>` or `<gazebo>`) and refuses a joint named twice.
