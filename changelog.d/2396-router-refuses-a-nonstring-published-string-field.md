### Fixed

- **simulation/mujoco**: the agent dispatcher's validation layer promises "no raw Python `TypeError`" and checks vectors "before the value reaches numpy / MuJoCo", but a scalar field the schema publishes as a string had no such layer, so a non-string value was carried into the method body and failed there. Across the published surface 39 probes escaped as raw exceptions on 13 `(action, field)` pairs - `AttributeError: 'int' object has no attribute 'lower'` from `add_robot(data_config=)`, `TypeError: stat: path should be string ... not list` from `load_scene(scene_path=)`, `unhashable type: 'list'` from `save_state(name=)` - none naming the field the caller sent. The silent form was worse: `save_state(checkpoint_name=1)` reported success and stored the state under an int key, so `load_state(checkpoint_name="1")` answered `Checkpoint '1' not found. Available: [1]` and that state stayed unreachable for the session. Refuse a non-string at the dispatcher, naming the field, the value and the spelling the caller used; the enforced set is derived from the schema at import time so a field published later is covered without a second list. Only the type is refused - `""`, a `str` subclass and `None` are unchanged, and the Python path still reaches `entity_name_error`. `keyframe` is now published as `["string", "integer"]`, matching the `str | int` its method, docstring and docs already document.
