### Added
- **docs guard (cosmos3)**: tie every embodiment enumeration to `EMBODIMENTS`, so adding a cosmos3 embodiment cannot leave a surface documenting a smaller accepted set than `create_policy("cosmos3", embodiment=...)` takes. The set is enumerated nine times by hand and nothing checked any of them - the provider-level guard grades *providers*, so an embodiment added to an existing provider was graded by nothing. Six are on the pages a reader consults: `docs/policies/cosmos3.md`'s front matter, its `## Embodiments` table, the first example's `# droid | umi | ...` comment, the domain/raw-dim/bundled-stats table, the bundled-vs-unbundled count above it, and the README provider row. Three more are graded for the same reason: the README quickstart's `Embodiments: ...` paragraph, which sits under the runnable rollout command (and states three of `droid`'s entry facts), plus the `Available embodiments:` sentence in the package docstring and the `embodiment:` `Args:` parenthetical on `Cosmos3Policy` - both read through `__doc__`, so a reflow cannot disarm them. Per-embodiment facts are graded too: `domain` and `raw dim` against the entry, the `bundled stats` column against the shipped `stats/<domain>_stats.json`, and the quickstart's stated width / chunk / fps against the entry.
