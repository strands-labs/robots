### Fixed

- **simulation/mujoco**: report a floating base for a robot that declares no joint. The kinematic-tree walk that recovers an unnamed `<freejoint>` could only be seeded from a body carrying one of the robot's declared joints, so it was unreachable for an aerial robot -- whose rotors are forces applied at sites on the airframe (`mjTRN_SITE`), leaving `robot.joint_names` empty. Its base read as absent: `get_observation` returned no state at all for a robot in the scene and moving, and `start_recording` declared a dataset with no `observation.state` column while still recording the `action` columns, so an episode captured a demonstration with nothing to condition on and reported success. The walk now also seeds from the bodies the robot's own actuators act on, resolved through the new `scene_ops.actuator_target_body_ids` and required to carry the robot's namespace (an actuator recognized by the joint id it drives can otherwise be borrowed from a machine that replaced the scene, since a stored id does not survive a recompile). A sibling free-jointed task object -- including one shipped inside the robot's own MJCF under its namespace, as every Menagerie grasping scene is authored -- is still never taken for the base, and every robot whose base already resolved answers unchanged.
