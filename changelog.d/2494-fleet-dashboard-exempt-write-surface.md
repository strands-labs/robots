### Fixed

- **examples/fleet**: the read-only dashboard now names the write path it keeps. `restrict_to_subscribe_only` refuses `send` / `tell` / `broadcast` / `emergency_stop` / `publish_step` and confines raw `publish` to the peer's own namespace, and the docstrings described that as replacing "every command-capable method" - but `publish_safety_event`, which puts a sample on the peer's own `safety/event` topic and appends a signed record to the audit trail this dashboard renders, is reachable on the restricted peer. It has to be: the mesh's own `_on_safety_estop` / `_on_safety_resume` handlers call it to record this peer's lockout transitions, two of those calls outside a `try` and the guarded ones catching only `(TypeError, ValueError, OSError)`, so refusing it would raise inside a Zenoh subscription callback on the safety path rather than guard anything. The exemption, its reason and its bound (the peer can only ever name its own `peer_id`) are now documented where a reader auditing "can this peer write?" will find them, and a new test classifies every public `Mesh` method as refused, confined, read-only, or documented-exempt, so a method added to `Mesh` cannot land on a peer advertised as read-only without a decision.
