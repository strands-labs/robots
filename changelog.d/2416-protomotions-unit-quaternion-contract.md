### Fixed

- **policies/protomotions**: `quat_rotate_inverse` and `extract_yaw_quat` now normalise their quaternion input and refuse one that cannot define a rotation. Both implement the Rodrigues form, which is only valid for a unit quaternion, so a quaternion scaled by any factor - which encodes the same rotation - was read as a different one: a `|q| = 0.924` orientation (the midpoint of two linearly interpolated samples) was read as a heading 6.2 degrees off and shortened a 1.0 rad/s world yaw rate to 0.707, and an all-zero orientation returned the angular velocity with its sign flipped. This matches the three other world-to-body helpers in the package, all of which already normalise, and the same-layer `policies/wbc/control` sibling, which refuses the degenerate case. Input dtype is preserved.
