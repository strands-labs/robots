### Fixed

- The dashboard settings store now holds all four of its numeric keys to one non-finite domain, instead of two of them. `agent.temperature` and `mesh.camera_hz` go through `_finite_float`, which refuses `inf`, `-inf` and `nan` by name and says why - a non-finite value would be written to `settings.json` as the bare `Infinity` token, which is not JSON, and one such write bricks the config screen for every browser. `agent.max_tokens` and `mesh.port` converted with a bare `int()` under `except (TypeError, ValueError)`, and `int(float("inf"))` raises neither of those - it raises `OverflowError`. So a non-finite value in an integer slot escaped the refusal altogether and neither coercion path answered: `update_strict`, whose contract is that an invalid value is reported and never stored, raised instead of naming the key, and the lenient path raised out of `load` itself. That second half is the worse one, because the lenient path exists precisely so that one unusable value degrades rather than taking anything else with it: a process-scoped `settings.override("agent", "max_tokens", float("inf"))` left `load`, and therefore `get` and `apply_mesh_env` and every other setting in the tree, raising for as long as the override was set. `json.loads` accepts the bare `Infinity`/`-Infinity`/`NaN` tokens, so a request body is one of the ways such a value arrives - which is the same reason `_read_file` already refuses them for the file. The four keys are now one roster, `_NUMERIC_KEYS`, read by both the strict path and the lenient degrade; the degrade had spelled their union as a second literal tuple, which is what allowed the two halves of the domain to drift apart on the one value neither literal named. `_finite_int` mirrors `_finite_float` so that non-finite is one class with one message, which also corrects `nan`: it was already reported, `int()` raising `ValueError` for it, but as "is not an integer" - a description of how the value was spelled rather than of what it is. It also catches `OverflowError` from the conversion itself, for a non-finite that is not a `float` instance and so is invisible to an `isinstance` check: `numpy.float32("inf")` and `Decimal("Infinity")` both convert that way. Pinned by `TestANonFiniteNumberIsReportedNotRaised` in `tests/test_dashboard_settings_value_domain.py`, which crosses all four keys with all three spellings on both paths and asserts, on the lenient one, that the rest of the tree still reads; 13 of its 31 cells fail on the pre-fix tree and the other 18 pass on both, pinning that the two float keys were already right and that the integers a key can legitimately hold - including `"8"` and `1.0` - are still held.
