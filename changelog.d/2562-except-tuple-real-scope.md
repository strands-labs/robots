### Fixed
- **exception handling**: an `except` tuple no longer names a class another member of the same tuple already covers. `except (FileNotFoundError, OSError)` collapses to `except OSError`, so the covered name contributed no scope, only the impression of a smaller superset than the handler had -- and where the prose on the handler enumerated the tuple, that impression became a claim it did not keep: `BridgeTransport.put` named three classes under a docstring reading "everything else propagates" while catching twenty-one, absorbing `NotImplementedError` on the same publish path that `mesh.sensors` re-raises it to avoid dropping a tick silently. Dropping the covered member at 25 sites is a no-op -- the absorbed set is unchanged -- and the prose that enumerated a tuple is corrected. No linter reports the shape (ruff's `B014` covers a duplicate member only), so it is refused in a gate over `strands_robots`, `tests`, `tests_integ` and `examples`. Narrowing a handler's effective surface remains a per-site behaviour change, and a third-party exception tree is left alone because a dependency can re-parent its classes between releases.
