### Fixed

- **tools/g1**: `use_unitree` now reports the `mutative` and `high_danger` classification on a call that FAILED, not only on one that succeeded. The error envelope built none of those keys, so five of the six outcomes a call can reach - DDS unavailable, client `Init()` failure, a raised RPC, a parameter mismatch, an unknown operation - came back with no classification at all, and `res.get("high_danger")` read a `loco.ZeroTorque` whose fate is unknown exactly like a `loco.GetFsmId` that is harmless. That is the outcome where the flag matters most: an RPC answering `RPC_CLIENT_API_TIMEOUT` is not evidence the command never landed, and an unanswered `loco.SetVelocity` is consistent with a robot that is walking. A read now reports `high_danger: false` rather than omitting the key, so absent and `False` are no longer the same answer, and the classification is applied after `_execute`'s diagnostics are spread in so `available_operations` and `expected` survive alongside it and cannot shadow it.
