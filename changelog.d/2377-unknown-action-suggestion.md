### Fixed

- **Simulation tool**: an unknown ``action`` now names the published action the caller probably meant. ``action`` is the one parameter every call must supply and the only one with no usable default, so it is where a typo is most likely to land - and it was the one parameter whose refusal named neither a candidate nor a way to find one, while a misspelled robot one frame away got a close match, the available names, and the discovery action from the same ``close_match_hint`` helper. ``sim(action="set_joint_position")`` now answers ``Unknown action: set_joint_position. Did you mean: set_joint_positions, ...?`` plus the size and location of the action vocabulary, so a name resembling nothing still learns the set is closed. Suggestions are drawn from the published enum only, never from the wider Python router, so a suggestion is never an action the agent boundary refuses.
