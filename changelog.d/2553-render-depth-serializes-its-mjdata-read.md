### Fixed

- **simulation/mujoco**: `render_depth` now copies mjData into the renderer under the simulation lock, like `render` and `get_frame` already did. All three drive the same `update_scene` + `render` pair, which copies `xpos`/`xquat`/`xmat` and dereferences `data.contact`, so an unserialised read races a concurrent `mj_step` and yields a torn depth map or a native crash; the blanket dispatch lock covers the tool surface only, so the camera-recorder daemon, a `PolicyRunner` worker and a direct Python call held nothing. With a policy worker stepping on its own thread, depth reads were landing inside a physics step while no RGB read was. What `render_depth` reports is unchanged - the metric bounds, the grayscale PNG bytes and the unknown-camera refusal are byte-identical - and the frame buffer is now copied inside the lock so the sanitize and PNG encoding still run unlocked.
