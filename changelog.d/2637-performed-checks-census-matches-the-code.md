### Fixed

- **mesh**: `validate_input_frame`'s `Performed checks:` census now names the checks the function performs. Its value rule was stated as coercibility -- "coercible to `float`, finite, within `+/- MAX_INPUT_VALUE_ABS`" -- where the function checks the type, so `True`, `False`, `numpy.bool_(True)` and the string `"1.0"` were all described as admitted and all four are refused. The `bool` refusal is the one check carrying a comment explaining itself, because `bool` is an `int` subclass and `True` would otherwise reach an actuator as a `1.0` command, and the census named it nowhere. The envelope it cited was `MAX_INPUT_VALUE_ABS`, the constant captured at import, while the body applies `_input_value_abs()`, which re-reads `STRANDS_MESH_INPUT_VALUE_ABS` per call: with the var narrowed to `10.0` after import the census reported `720.0` and a value of `365.0` was refused. `merge_slew_baseline` already named the resolver for the same envelope. No code changed. A new guard grades every `Performed checks:` census against its own function's body -- a census may cite only a domain the body reads, and every type a positive `isinstance` gate refuses must be named -- with `validate_command` satisfying both rules unchanged as the control.
