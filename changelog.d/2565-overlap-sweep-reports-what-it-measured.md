### Fixed

- **ci**: the open-set overlap sweep no longer claims more than it measured. `scripts/check_merge_base_overlap.py --all-open` intersects changed *paths*, so a test resolving its population from a filesystem walk is invisible to it - the grader is coupled to files it never names, and its intersection with the sibling it grades is empty. A clean run nonetheless printed `No untested composition in the open set`, which is a claim about compositions rather than about paths, and a reader who trusts it stops looking. #2557 added a whole-tree ASCII grader and merged in a batch with #2559 and #2560, both of which added exactly the tool-result prose it scores, at a pairwise path intersection of `[]` with each; the batch was safe only because it was checked by hand. The clean line now states the two intersections it actually ran, and every report ends with the composition class no relation in it can describe. Widening the path set to the walked root is deliberately not the remedy: measured on the open set of 9 it selects 11 of 36 pairs, 9 of them new and none a defect, because the graders that reach furthest are rooted at the package. The relation that does settle it - composing the branches and running the grader - needs a checkout this mode deliberately does not have, and stays a manual step documented in AGENTS.md.
