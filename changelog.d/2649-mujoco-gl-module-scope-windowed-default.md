### Fixed

- **tests**: thirteen module-scope `MUJOCO_GL` defaults named `glfw`, a windowed GL backend that cannot render on a host with no window server, and now name the platform-guarded form the notebooks and guarded examples already use. `MUJOCO_GL` is read once, at `import mujoco`, so a module-scope default selects the backend for the whole file while one inside a test function runs too late to select anything. `glfw` fails worse than `cgl`: `cgl` is refused at import with a message naming the variable, `glfw` is accepted, the render probe then warns that rendering is unavailable and names the missing `DISPLAY` but not the value that asked for a window, and camera observations are skipped from there on - so the caller's failure is whatever it was doing with those frames. Driving the multi-robot recording path headless with `MUJOCO_GL` unexported, `start_recording` succeeded and declared its four camera features and every `add_frame` was then refused as a dataset feature mismatch listing those four keys: 0 frames, 0 episodes, 0 MP4 files. The same run now records 12 frames, 1 episode and 4 MP4 files. `tests/` is unaffected in CI, which exports `MUJOCO_GL=osmesa`; `tests_integ/` is in no workflow, so nothing exported it there. A bare `"egl"` was not an option: it is not in MuJoCo's valid set on Darwin, where `glfw` works today. `tests/test_examples_mujoco_gl.py` now also refuses a module-scope windowed default and scans `tests_integ/`, AST-scoped to module level so a backend name that is the value under test stays out of scope by construction.
