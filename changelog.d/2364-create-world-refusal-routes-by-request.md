### Fixed

- **`create_world` on a live world now routes by the request instead of offering `reset`.** A second `create_world` is refused (a world cannot be rebuilt under a live scene), and `Robot("so101")` returns an engine whose world is already created and populated, so that refusal is the first thing such a caller meets. It offered the same two remedies for every request. `reset` applies no `create_world` parameter - a caller who asked `create_world(terrain="rough")` and followed the advice got `status="success"` and a flat world (`nhfield=0`); the same for `timestep=0.001` (still `0.002`) and `gravity` (still `-9.81`). `destroy` then `create_world` does apply them but discards every robot and object, which the refusal never said. `set_timestep` / `set_gravity`, published actions that apply exactly those two parameters to the live world and keep its contents, were not mentioned. The refusal now names what the live world holds and routes `timestep` / `gravity` to those setters, `ground_plane` / `terrain` / `difficulty` to `destroy` with its cost stated, and a bare call to the world that is already usable. Refusing is unchanged: it is still an error and still leaves the world exactly as it was.
