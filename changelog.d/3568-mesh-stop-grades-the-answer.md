### Fixed: `robot_mesh(action="stop", target=...)` over the built-in mesh path reported a halt for any answer that was not a raised exception, so a peer that said it did not stop, a rejection carrying no result, a request that timed out and a `Mesh.send` precondition error were all `status="success"` with an `ok=True` audit row. The branch now grades the answer: a delivered result is read with the same rule the fleet-wide stop uses, and the two answer kinds only this path carries -- a `type="error"` rejection and a timeout, which for one named target is a failure to confirm the halt -- turn the result into an error naming the target and its answer, audited `ok=False` and logged at CRITICAL. An answer that reports the fact neither way is still a success.
