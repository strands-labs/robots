### Fixed

- **training**: `tests/training/test_lerobot_e2e.py` trains a real ACT policy in the unit suite, and lerobot's `ACTConfig` defaults `pretrained_backbone_weights` to `ResNet18_Weights.IMAGENET1K_V1` - so the one required status check gating every pull request fetched 46,830,571 bytes of `resnet18-f37072fd.pth` from an external CDN on every run. The spec already asks for ACT from scratch, so the download bought its assertions nothing while making the merge gate depend on that host answering, and a CDN blip was indistinguishable from a regression in `training/`. The spec now clears the knob and the loop asserts it reaches no external host.
- **training**: `LerobotTrainer.build_command` renders a `None` in `extra` as the YAML null literal. Python's text for `None` is a plain YAML scalar, so a `str | None` field given `--key=None` was assigned the string `"None"` while the in-process path assigned `None` - and `"None"` reaches torchvision as a weights name (`KeyError: 'None'`), so the shelled-out path crashed on the spec the in-process path ran. Only the null literal is translated: a rule keyed on truthiness would clear a field for `0` or `False`.
