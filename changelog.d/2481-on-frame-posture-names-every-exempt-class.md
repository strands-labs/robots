### Fixed

- **simulation**: the `on_frame` hook's documented failure posture now names both exception classes the rollout loops exempt from it. Every surface that describes the posture - `run_policy`, `eval_policy`, `evaluate_benchmark`, `PolicyRunner.run` and `PolicyRunner.evaluate` - promised that any exception other than `CooperativeStop` is logged at WARN and tolerated, but a `RecordingFrameError` is data loss rather than telemetry: it is neither logged nor counted against `max_onframe_failures`, and it propagates on the first occurrence. A caller following the hook's own documented use (recording frames on the eval thread) was told the one failure most likely to reach them could not abort the eval. Behaviour is unchanged; a guard derives the exempt set from the handlers themselves so a third exempt class cannot be added without those surfaces being updated with it.
